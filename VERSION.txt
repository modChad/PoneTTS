PoneTTS
=======

Docker bundle for the PoneTTS voice server: 43 voices (0-32 My Little
Pony, 33-42 Team Fortress 2), 48 kHz mono WAV. Voice backend for Pony Pony
Paradise (PPP) and SillyTavern.

Updated: 2026-09-28
Previously: TTSMODv4-BERK (server v2.8, pass 1 of 2)

NVIDIA ONLY
  PoneTTS needs an NVIDIA GPU. AMD (ROCm) support has been removed. No
  local GPU? Use the Google Colab notebook in colab/.


QUICK START (Linux, or Windows via WSL2)
-----------------------------------------
  ./run.sh

  Installs any missing Docker pieces (CLI, Engine, Compose, buildx) after
  asking, detects your GPU and VRAM, picks a preset, writes
  docker-compose.yml, then builds and starts the server. Not on Linux, or
  want to do it by hand? See DISTRIBUTING.md.

  Windows: install WSL2 + Ubuntu, install the NVIDIA driver on Windows
  (not in WSL), clone into ~/PoneTTS (not /mnt/c) and run ./run.sh there.
  run.sh detects WSL, installs the NVIDIA Container Toolkit from NVIDIA's
  apt repo, and prints LAN-access steps (mirrored networking or netsh
  portproxy). The voice patch is downloaded automatically on first start.

  Before running: your GPU driver must work outside Docker (nvidia-smi should
  list your card). run.sh also checks for the NVIDIA Container Toolkit and offers to install it.

  First start downloads the ~12 GB model; allow up to ~20 minutes.


NAMES
-----
  Container / service   pone-ttsmod
  Image                 pone-ttsmod:cuda
  Volume                pone-ttsmod_release (model)
  Data folder           server/data (mounted at /app/data)
  Default port          8800
  SillyTavern URL       http://pone-ttsmod:8800/v1/audio/speech

  Upgrading from TTSMODv4-BERK: the volumes were renamed, so the model
  downloads again on first start. Afterwards you can remove the old ones:
    docker volume rm ttsmod_release ttsmod_sfx_cache


BUILD TARGETS
-------------
  runtime-cuda   CUDA 12.8, torch 2.11.0, Python 3.12 (required by
                 numpy 2.5.0)


PERFORMANCE PRESETS (MOSS_PERF_PRESET)
--------------------------------------
  quality    ~14-16 GB   vocoder on GPU
  balanced   ~9-12 GB    vocoder on CPU (server default)
  low_vram   ~7-8 GB     no CUDA-graph capture, shorter line cap
  potato     ~6 GB       as low_vram with the shortest line cap. Not
                         quantized: the model bundle has no int8 support

  run.sh suggests: under 7 GB potato, 7-9 GB low_vram, 9-12.5 GB balanced,
  above that quality.

  Switchable live from the web page at http://localhost:8800/


FEATURES
--------
  Endpoints
    /tts, /tts_stream/                     native synthesis
    /v1/audio/speech                       OpenAI-compatible (SillyTavern)
    /tts_to_audio/, /speakers,             XTTSv2-compatible (SillyTavern)
      /set_tts_settings
    /st_cache/generate, /st_cache/         server-side clip cache
    /sfx                                   sound effects (Freesound / BBC)
    /voice_fx                              per-voice audio effects (web UI)
    /preset, /voice_blend, /normalize,     tuning and diagnostics
      /gpu, /health, /speakers
    /                                      browser test page

  Speech quality
    - Long text split into clauses at . ! ? : ; and em-dashes, with short
      pauses, so long paragraphs and poems don't cut off (up to 200 clauses)
    - Newlines in input handled correctly
    - Stuck-word detection and retry (MOSS_FIX_STUCK_WORDS, on by default)
    - Pronunciation fixes: pronunciations.txt, optional voice patch LoRA
      (server/voice_patch/), per-speaker voice blend, and per-request
      client_pronunciations overrides
    - Optional Whisper-based pronunciation check (MOSS_FIX_PRON,
      MOSS_AUTO_RESPELL; off by default)

  Voice effects and streaming
    - robot, radio, cavern, helium, changeling: set per voice in the web
      page, applied for every caller (webui, SillyTavern, PPP)
    - /tts_stream/ streams sentence by sentence

  Operations
    - Request log shows which client called: webui, sillytavern,
      ppp (via X-Client-App header) or unspecified
    - /sfx validates downloads before caching; MOSS_SFX_ALLOW_NETWORK=0
      makes it cache-only (no outgoing requests)
    - Voice patch and st_cache/ are bind-mounted from server/, so adding the
      patch or reading cached clips needs no rebuild
    - Entrypoint re-applies the voice patch and the torchopt bundle fix on
      every start, and fails fast with a clear message if the GPU isn't
      visible


KNOWN ISSUES
------------
  - The NVIDIA image hasn't been confirmed on real hardware yet.


CHANGES IN THIS RELEASE
-----------------------
  - NVIDIA only: removed AMD/ROCm support (the runtime-rocm Docker target,
    AMD detection in run.sh, the AMD compose example)
  - One data folder, server/data (MOSS_DATA_DIR; Docker: /app/data): settings,
    history, clip and sound-effect caches, pronunciations.txt and the
    Freesound key. Older locations are moved there on first start; re-run
    ./run.sh once so the compose file mounts it. Starting files live in
    server/defaults/ instead of being edited in place
  - server/prepare.py runs the setup steps (model download, voice patch,
    bundle fix) for Docker, setup.sh, setup.bat and Colab alike
  - Removed the root copies of setup.sh, run_server.sh, requirements.txt
    and the voice patch README (use the ones in server/)
  - Google Colab notebook added in colab/
  - The voice patch is downloaded on first start instead of stored with
    Git LFS
  - Stop generations: POST /cancel?scope=mine|all, plus "Stop mine" and
    "Stop all" buttons on the web page. Stops between sentences (the
    current one finishes); queued requests never start; later requests are
    unaffected. /health now lists active and queued requests ("activity"),
    shown live on the page
  - Generation history: every generated line is saved to server/history/ as
    <time>_<voice>_<first-words>.wav + .json, newest 500 kept
    (MOSS_HISTORY_MAX, 0 = off). Web page lists them with play, download,
    delete and voice/client filters. run.sh and the compose snippet mount
    ./server/history
  - Long sentences (over 20 words) are also split at commas, packed into
    5-15 word pieces with a short 0.12s gap. Commas beside short list items
    are never split, so lists and Oxford commas stay together
    (MOSS_COMMA_SPLIT_MIN_WORDS)
  - Loop guard cuts repeats by finding where the sentence's ending first
    appears in the transcript, so partial repeats ("...is complete? ...is
    complete?") are caught too; the old word-count rule is kept as a fallback
  - Failed sentences (the loop guard hears under half the words: silence,
    hiss or gibberish) are regenerated up to twice, whatever
    MOSS_FIX_STUCK_WORDS is set to (MOSS_LOOP_GUARD_MIN_HEARD,
    MOSS_FAILED_CLAUSE_RETRIES)
  - Loop guard now also checks sentences that run more than 1.6x their
    expected length (MOSS_LOOP_GUARD_REL_MULT), not only ones that hit the
    token cap. Catches clean double reads, which end on their own well inside
    the cap; Whisper still only runs on suspicious sentences
  - Renamed TTSMODv4-BERK to PoneTTS; container, images and volumes renamed
    from ttsmod to pone-ttsmod
  - run.sh installs missing Docker CLI / Engine / Compose / buildx (pacman,
    apt, dnf, zypper; uses Docker's official repo packages if configured),
    starts the Docker service, falls back to standalone docker-compose,
    and explains how to join the docker group
  - Added .gitignore
  - run.sh on Arch: if a CLI-only package (e.g. docker-cli-bin) is installed,
    it explains that "docker" replaces it and lets pacman ask, instead of
    failing on the conflict; Docker Desktop (engine in a VM, no local
    dockerd) is no longer treated as a missing engine
  - run.sh uses plain-text build progress when its output is piped or
    logged (fixes "failed to get console: provided file is not a console"
    with "./run.sh | tee build.log")
  - entrypoint.sh explains a failed model download (exit code, likely cause,
    free disk space) and waits 60s before exiting, instead of crash-looping
    silently; the first-run marker now lives in the model volume as the
    comments always said
  - Model download uses the plain HuggingFace downloader by default
    (HF_HUB_ENABLE_HF_TRANSFER=0, HF_HUB_DISABLE_XET=1). The fast downloaders
    got the container killed mid-download on the test machine; the
    plain one finished the full download in 7m40s
  - run.sh caps the container's system RAM (all but a quarter of RAM,
    keeping at least 3 GB back, swap off for the container), so running out
    of memory restarts the server instead of taking down the desktop
  - run.sh checks for the NVIDIA Container Toolkit and offers to install it
    (pacman, or apt/dnf/zypper when NVIDIA's repo is set up), then restarts
    Docker
  - run.sh preset thresholds: 6 GB cards now get potato (was low_vram);
    warns under ~5.5 GB
  - potato relabelled everywhere: it was described as int8 (bitsandbytes),
    but the model bundle only supports "none" or torchao fp8
  - The Docker image installs exactly one onnxruntime package,
    onnxruntime-gpu (the build fails if its CUDA provider is missing).
    Previously faster-whisper's CPU package could overwrite the GPU one
  - Server logs a clear warning and uses the CPU vocoder when quality's GPU
    vocoder can't run (no CUDA provider), instead of falling back
    silently
  - server/README.md: default preset corrected to balanced
